    RETAKE / DOCUMENTATION

    Video walkthroughs
    of your web app.

    Retake records video walkthroughs of websites and web apps. Your coding agent prepares the walkthrough; Retake runs it in a browser and saves a video for you to review.

    • You choose what to show: a URL, and one sentence about the result the viewer should see.
    • Your coding agent, such as Claude Code or Codex, looks at the page and prepares the steps: what to click, what to type, what to wait for.
    • Retake performs those steps in a browser and records the page as a video.
    • You watch the video and say what to change.

    The video shows your website or web app, in one browser tab. On a Mac, Retake can also record one Mac app’s window (see Record a Mac app). It does not record your whole desktop, other windows or native mobile apps.

    See an example ↓Already set up? Record, review & rerun →

    An example

    Say your app runs at http://localhost:3000 and you want to show how a project is made. In the Retake window you type the URL and one sentence:

    Show a new user creating a project and finding it in the dashboard.

    You get a silent video, outputs/<demo name>/demo.mp4, of your app doing that: the clicks, the typing and the new project in the dashboard. Next to it are a still image of each scene and proof-log.md, which lists every step and whether it worked.

    This example is illustrative. For real recordings made with Retake, see the examples on the homepage.

    What you need

    • Node.js 20 or newer. Retake is used daily on macOS. Linux is not verified beyond CI.
    • Claude Code or Codex, installed and signed in. The Retake window uses it to prepare your first recording, on your own plan. Other coding agents, such as Cursor, can use Retake from their own chat: see Use it from your coding agent.
    • The site to record, at a URL this computer can reach: a public link or localhost. Use a test account or a local copy, because the recording really clicks and types in it.

    No Retake account or Retake API key. Setup downloads Chromium, the browser Retake records in, once.

    01 / GET STARTED

    Install & open the window

    Run these in your terminal, one at a time. The last one keeps running.

    Terminal · new workspace
    npm install -g retake-demos
mkdir my-demos && cd my-demos
retake install
retake doctor
retake ui
    • retake install makes the folder a workspace (demos/, outputs/, .env and ignore rules), downloads Chromium and registers Retake with Claude Code. Its output says if that registration failed; it only matters later, for using Retake from your agent.
    • retake doctor lists anything still missing.
    • retake ui starts the Retake window.

    Keep that terminal open, then open http://localhost:4310 in your browser. This is the Retake window, not your app. Your app stays at its own URL.

    Prefer not to install globally?

    Use npx retake-demos install inside your workspace. The other commands on this page assume the global install. With npx, replace the retake prefix with npx retake-demos.

    Source: README: Install · CLI setup and doctor

    Make your first recording

    On a new workspace, the Retake window asks four short questions:

    1. Paste the URL to record. A public link or localhost.
    2. Your videos, in your colours. Retake reads your site's colours and logo and shows the opening card it made from them.
    3. What should the viewer see? One sentence about the result, not every click.
    4. Choose the final sound. No voiceover is fine. Whatever you choose, the first draft is silent.

    Before you press Make first draft: the agent clicks, types and submits in your app for real, once to check the steps and again while recording. Use a test account or a local copy, and keep it away from anything that pays, sends or deletes. Your coding agent sends what it reads from the page to its own provider, and the work counts toward your Claude Code or Codex plan.

    Press Make first draft. Retake starts Claude Code, or Codex if that is what you have, with only Retake's tools: it cannot run shell commands. The agent inspects the page, writes the steps and checks them in a dry run; then Retake records a silent draft. Progress appears in the window, and so does any question the agent needs answered. Keep the window open until it finishes.

    If your site needs a login, the window asks for a demo account in a small form. The agent signs in with it but never sees the password. See Record behind a login.

    Source: The window's first-run questions · How the window starts your agent

    Review the video

    When it finishes, the window says Your first draft is ready. Press Open first draft to play it in the window, with its scenes. The files are in your workspace: the video is outputs/<demo name>/demo.mp4 and the steps are in demos/<demo name>.yaml. Find your files lists the rest.

    Watch the whole video before you share it. Can you see each action and its result? Is the important text readable? Is anything private visible, including while pages change?

    To change it, ask your coding agent: shorter, a different ending, captions on. The window makes the first draft; changes after that go through your agent, which is the next step.

    02 / KEEP GOING

    Use Retake from your coding agent

    After the first draft, you ask your coding agent for changes and new recordings in its own chat. It reaches Retake through MCP, the standard way coding agents connect to extra tools.

    Claude Code: retake install already registered Retake. Restart Claude Code, because a session only picks up new tools when it starts. Then ask for what you want in plain words. You do not need to write the steps yourself.

    Example request · replace the app URL and workflow
    Use Retake to record my app at http://localhost:3000.
Show a new user creating a project and finding it in the dashboard.
Start with a silent preview. Keep the camera static.
Use a demo account. Hide account details and stop before any paid action.
Inspect the real page before choosing selectors. Validate and dry-run
before recording. Show me the preview and proof log for review.
Do not add narration until I approve the recording and its script.

    This is an illustrative request, not a tested workflow for your app. The agent must inspect your actual routes and selectors, and save the steps in demos/<name>.yaml, where the Retake window can find them. Keep retake ui running to watch progress and review the result.

    Codex, Cursor and other MCP clients

    Run this inside your Retake workspace. It prints the exact command, arguments and workspace path for your installation; use that output rather than a server path copied from a tutorial.

    Terminal · print your client configuration
    retake agent

    Claude Code

    If retake install reported that registration failed, or the Claude CLI was missing, use the Claude Code command printed by retake agent, then restart.

    Codex

    retake agent prints a [mcp_servers.retake] block for ~/.codex/config.toml. Add it without replacing unrelated settings, then restart Codex.

    Cursor

    retake agent prints JSON under mcpServers for .cursor/mcp.json or your client's MCP settings. Merge the Retake entry, then reload or restart the client.

    These are the configuration paths Retake's CLI prints, not a claim that every client version has been tested. Preserve any other MCP servers in your configuration. Or ask your agent to do it:

    Copy this request to your coding agent
    Help me connect Retake to this coding agent.
From my Retake workspace, run retake agent and use the configuration
it prints for this client. Preserve existing MCP servers and settings.
Tell me what changed and whether I need to restart.
Do not start my app or record anything yet.

    From its own chat, your agent will not start your app unless you add RETAKE_ALLOW_START=1 to Retake's MCP settings. Leave it off unless you want that.

    Source: CLI: install, agent and mcpServer · Tool permissions · Recording skill

    Record a Mac app

    On a Mac, Retake can also record one app’s window. Type the app’s name, such as TextEdit, in the window’s first box instead of an address, or ask your agent for a demo of the app. The video shows only that app’s window, sharp, with a pointer drawn where each click lands, and you can keep working while it records.

    It needs a one-time setup, and the window lists each item with its fix before anything starts: cua-driver (the tool that clicks and types in the app) with its Accessibility and Screen Recording permissions and its telemetry turned off, and Retake’s window recorder, built once with retake build-native. Retake never installs or grants any of these for you. retake doctor --native shows the same list in a terminal.

    Like a web recording, an app recording really clicks and types in the app: use test data. With launch: fresh, Retake restarts the app first, and stops if the app has unsaved work.

    In the manifest, app: TextEdit replaces url:, and controls are named by role and name, such as role=button[name="Sign in"]. retake scout --app TextEdit lists them.

    Share the takes

    To send several finished videos as one page, ask your agent for a share link, or run retake share with the demo names in watching order. The page plays them one at a time with a Next button, shows each demo’s notes and steps, and lets viewers leave a comment at a moment in a video.

    The link opens on this Mac. With Tailscale it can reach your other devices. Hosted links for clients are not available yet, so check who can open the page before you send it.

    Watch an AI test your app

    Watch is for testing, not for making a video. It has three parts:

    • Sessions: a test script or an AI agent tests your web app while you watch in the Retake window, live or as a replay. Press Unclear on any moment that works but does not look clear, and your notes become a fix request your coding agent can pick up.
    • Journeys: your app’s key flows, kept as small scripts in your workspace, so the same test runs again whenever you like.
    • Nightly: every journey runs each night. You hear nothing unless something changed or failed; then one screen shows what changed, and Accept as normal makes it the new normal.

    Secrets the test names are blacked out. Read the Watch guide →

    03 / MAKE A KEEPABLE TAKE

    Record, review & rerun

    Each walkthrough is saved as a small text file in your workspace, demos/<name>.yaml: the URL, the steps and the captions. YAML is just a plain-text settings format, and this file is called the manifest. Your agent writes and edits it. Because the steps are saved, the next take does not start from scratch.

    Your agent runs the commands below for you; they are here so you can see, or run, each stage yourself. First prove the browser steps, then record, then render presentation changes from the saved recording. The commands use an existing, agent-authored manifest named demos/my-demo.yaml with name: my-demo. They do not create that file.

    Commands match published Retake 0.14.3 (its CLI source). run follows the manifest's sound settings and does not automatically force silence: for a silent take, set voiceover: false in the existing manifest and omit music.

    Terminal · validate, dry-run, record
    retake validate demos/my-demo.yaml
retake dry demos/my-demo.yaml
retake run demos/my-demo.yaml --no-master
retake check outputs/my-demo
    • Validate checks the schema and warnings.
    • Dry-run visits the app and performs selectors and waits without recording. It can still change app state. Use safe test data.
    • Run records the browser and renders the take using the manifest’s settings.
    • Check checks the media and output files. A pass does not prove the story, privacy or visual result is correct.

    Watch before you finish

    Open demo.mp4 in the window. Read proof-log.md and inspect the scene stills. Watch the whole cut: can you see the action and its result, read the important text, and confirm there is no private data, including during transitions?

    Your agent can use receipts to read step results and look to inspect frames. Neither replaces watching the exact final MP4. Hold delivery if an important check cannot be completed.

    Terminal · after preview review and any render-only edits
    retake render outputs/my-demo demos/my-demo.yaml --preset post-landscape --no-master
retake check outputs/my-demo

    Watch this rendered file again before sharing it. render uses the saved take and the current manifest to produce a new cut; it does not record the browser again. The manifest must still describe the actions in that take.

    Which kind of change?

    Words, captions, cards, music, pacing or format: edit the presentation and re-render the existing take. Review the resulting MP4 before sharing it.

    Clicks, routes, fixtures or visible page state: repair the manifest, validate and dry-run again, then record the browser again:

    Terminal · check the changed flow and record again
    retake validate demos/my-demo.yaml
retake dry demos/my-demo.yaml
retake run demos/my-demo.yaml --no-master
retake check outputs/my-demo

    This run performs a new browser recording. Confirm that another take is wanted before running it, and keep any approved deliverable safe before changing its output.

    Source: Published 0.14.3: run and render · run, render, receipts and look tools

    Voiceover & captions

    Choose voiceover, captions, both, or neither. They are separate presentation choices. A silent video can have captions; narration does not require visible captions.

    Keep the first preview silent. Approve the recording, then read and approve a continuous narration script before speech is generated. For a silent CLI take, explicitly set voiceover: false and omit music in the existing manifest before running it. Do not assume the recording command overrides sound settings.

    Voice choices depend on the version and provider configured in your workspace. Edge uses a speech service; local voices, where available, require their own model setup. Do not assume every voice supports your language or that every option runs without downloads or network access.

    Example request · independent presentation choices
    Keep this preview silent. Turn visible captions off for the final cut.
After I approve the recording, show me a continuous narration script.
Wait for my script and voice approval before generating any speech.
Use the existing take for narration and presentation changes.
Review the final MP4 for audio timing and a complete ending.

    For manifest editing, captions: false disables visible captions. Do not use a voice setting as a substitute for script approval. Ask your agent to follow the current voice setup in your workspace rather than guessing a provider configuration.

    Source: Published sound and caption settings · Caption controls

    Find your files

    Run commands from the same workspace. Keep the manifest in demos/ and preserve the raw take if you want to re-render later.

    Workspace · typical output, not a command
    demos/my-demo.yaml
outputs/my-demo/
  demo.mp4         # rendered video to review and share
  stills/          # scene images
  thumbnail.png    # poster
  proof-log.md     # step results, timing and failures
  take.json        # recording timeline used by the renderer

    --no-master skips the optional archival master.mp4. Launch cuts and other output choices can add covers, GIFs or contact sheets. Do not expect every optional artifact in every run.

    Rendered is not reviewed. Reviewed is not approved. Approval means a person accepted that exact file, not just its manifest or an earlier preview.

    Source: README: output files

    04 / WORK SAFELY

    Privacy & provider costs

    The workspace and rendering are local. That does not make the whole workflow offline or free: installation downloads packages and Chromium, recording contacts the target app, and your coding agent may send context to its provider under that provider’s plan.

    Optional model-backed drafting, suggestions and visual judgments can use a configured provider. Visual checks can send frames to a model. Speech choices can need network access or model downloads. Confirm providers, data boundaries and any charges before enabling them. Local capture is not permission to use a paid model key.

    Record behind a login

    Use a demo account. A login is saved once per site and every demo of that site signs in with it. When a demo needs one, the Retake window asks with a small form; without the window, save it in your own terminal. Do not paste passwords into agent chat.

    Terminal · save a demo login for one site
    retake login https://app.example.com

    On a Mac the login is kept in your Keychain, not in a project file. The agent signs in with ${LOGIN_USER} and ${LOGIN_PASSWORD} marked secret: true in auth.setup, before the camera, and never sees the values. The session is kept in .auth/ and Retake signs in again by itself when it runs out. retake logins lists the saved sites; retake login <url> --forget removes one. Older demos that use ${APP_PASSWORD} from .env keep working.

    For a login that needs a person, such as SSO or an SMS code, choose Sign in by hand in the window's form, or:

    Terminal · human sign-in
    retake login https://app.example.com --by-hand

    A real browser opens. Sign in yourself, then press Enter in the terminal to keep the session. secret: true hides logged values, not pixels in the video. Omit unsafe screens or cover private regions and review navigation transitions. Never approve a paid action just to make a demo pass.

    Source: README: login and secrets · Agent tools and visual checks

    Troubleshooting

    The window says it needs Claude Code or Codex

    The window makes the first draft with Claude Code or Codex on this computer. Install one, sign in, then try again. If its sign-in has expired, the window offers to sign in; you can also run claude auth login or codex login in a terminal.

    The agent cannot see Retake’s tools

    Check setup output. Run retake agent from the correct workspace, apply the client’s generated configuration and restart the agent. Until then, the local CLI remains available.

    The window or app does not open

    Run retake ui in the workspace and keep its terminal alive. The default window is http://localhost:4310. Your app is a separate server. Check its actual URL and port; do not have an agent start a process without your permission.

    Chromium or ffmpeg is missing

    Run retake doctor. If Chromium is missing, follow its retake install guidance. ffmpeg is bundled with the package; doctor reports a missing binary separately. Read the error before repeating a recording.

    A selector fails or the preview shows the wrong state

    Read proof-log.md. Have the agent inspect the real page, fix the selector or wait for the visible result, then validate and dry-run. Do not keep recording a failing flow. A reusable workflow is not self-healing.

    A render fails or does not show my changed workflow

    Check that the output contains take.json and its saved recording, and that you supplied the correct manifest. Rendering changes the presentation of an existing recording; it cannot add a browser interaction that was never captured. For changed clicks, routes or page state, validate and dry-run the repaired manifest, then use retake run demos/my-demo.yaml --no-master to record again.

    The video exists but is absent from the library

    Check that its manifest still lives in demos/. Do not delete the manifest after rendering. retake heal can recover missing manifests from saved recordings; inspect what it proposes before applying recovery.

    The workflow needs another window or a very long take

    Retake records one tab. Its default keepInTab folds new-tab links into that tab, but true multi-window flows are outside this scope. Split long stories into short demos. The README notes an approximate 180-cursor-move limit per take and that macOS is used daily; Linux is not verified beyond CI.

    Still blocked? Report an issue with the command, package version and a redacted error or proof log. Do not attach credentials, session files or private video frames. Known limits
